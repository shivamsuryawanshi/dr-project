1. What This System Does (The Domain)

MedExJob is a specialized recruitment platform designed specifically for the healthcare sector in India (Doctors, Senior/Junior Residents, Faculty, Medical Officers, Specialists, and Paramedical Staff).

Unlike traditional job boards (Naukri, LinkedIn), Indian medical recruitment is split into two distinct models:

  • Private Sector Jobs: Standard hospital, clinic, and consultancy postings. Recruiters create jobs, set salary/experience, manage applicants, and review candidate CVs.
  • Government Circulars & Public Hospital Notices: Public institutions (AIIMS, PGIMER, State Health Services, ESIC, Railway Hospitals) release large official PDF notifications (typically 5 to 35 pages). These contain dense department-wise vacancy matrices, reservation breakdowns (UR, OBC, SC, ST, EWS), recurring walk-in interview schedules, qualification checklists, and application guidelines.

To eliminate hours of manual data entry, MedExJob includes an automated AI/OCR Circular Extraction Engine that ingests government PDFs, parses multi-department vacancy tables, normalizes designations, and generates browsable, filterable candidate jobs.

3. Local Development Quickstart

Step 1: MySQL Database Initialization

CREATE DATABASE medtech_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

Verify your database password in backend/src/main/resources/application.yml:

spring:
  datasource:
    url: jdbc:mysql://localhost:3306/medtech_db?useSSL=false&serverTimezone=UTC&allowPublicKeyRetrieval=true
    username: ${DB_USERNAME:root}
    password: ${DB_PASSWORD:shivam123}

Step 2: Start Backend Service

cd backend
mvn clean install -DskipTests
mvn spring-boot:run

Backend runs on http://localhost:8081. Actuator Health: http://localhost:8081/api/actuator/health -> {"status":"UP"}.

Step 3: Start Frontend SPA

cd frontend
npm install
npm run dev

Frontend runs on http://localhost:5173.

No Local CORS Setup Needed

In frontend/vite.config.ts, a proxy is configured: any call from React to /api/* is transparently forwarded by the Vite dev server to http://127.0.0.1:8081 without triggering browser CORS blocks.

One-Click Windows Start

On Windows PowerShell, run .\start-local.ps1 from the root folder. It checks MySQL, verifies Java 17 and Node.js, and launches both services in separate terminal windows automatically.

5. The AI & OCR Circular Extraction Pipeline

This is the core proprietary feature of the platform. Medical job advertisements are usually complex multi-page PDF documents. Here is how the extraction pipeline operates:

  1. Upload & SHA-256 Fingerprint: Admin drops a circular PDF into AiBulkJobUploader.tsx. Backend calculates a SHA-256 hash to prevent duplicate reprocessing.
  2. Native Text Extraction: BulkGeminiRecruitmentExtractionService.java extracts native text using Apache PDFBox 3.x.
  3. OCR Fallback for Scanned Circulars: If extracted text is fewer than 250 characters (common with scanned government orders or Hindi circulars), RecruitmentOcrService runs Tesseract OCR.
  4. Multimodal Gemini Parsing: The PDF bytes and extracted text are dispatched to Gemini (gemini-2.0-flash) via RecruitmentAiExtractionClient.java. Gemini returns a structured JSON payload containing:
    • Organisation name, circular reference number, and location/state.
    • Full multi-department vacancy table with columns (Department, UR, OBC, SC, ST, EWS, Total).
    • Cadre breakdown (Senior Resident, Junior Resident, Faculty, GDMO, Medical Officer).
    • Walk-in interview dates, venue, application deadlines, and fee details.
  5. Heuristic Table Parser Fallback: If Gemini is temporarily unavailable, RecruitmentExtractionService.java uses an internal regex/table parser and sanitizes the output via RecruitmentFieldSanitizer.java.
  6. Publishing to Live Jobs: Admin reviews the extracted table in the preview workspace, makes edits if needed, and clicks "Publish". VacancyJobPublisher.java creates the parent Recruitment record, links individual VacancyRecord entries, and publishes clean Job listings visible to candidates.

7. Engineering Gotchas & Edge Cases (Must Read)

1. Right-to-Left Scanning in Circular Tables

In Indian medical vacancy tables, the column order is almost universally:
| Department | UR | OBC | SC | ST | EWS | Total Posts |
Never scan left-to-right to find the vacancy count. Column 1 is almost always the Unreserved (UR) category count, NOT the total. Scanning left-to-right causes the parser to record the UR quota as the total vacancy. recruitmentBreakdown.ts and rawNoticeParser.ts first match explicit header names ("Total", "Grand Total"), and if absent, scan columns rightmost-to-left.

2. False "Medical Officer" Role Tagging

Many official circulars mention the term "Medical Officer" in committee signatures, administrative notes, or footers even when the actual vacancies are strictly for "Senior Resident" or "Associate Professor". We recently added strict regex boundaries to prevent circulars from being incorrectly tagged as Medical Officer posts. Be careful when modifying cadre regexes.

3. Hibernate ddl-auto: update Limitations

The backend is configured with hibernate.ddl-auto: update. This will add new tables and new columns automatically, but it will never drop obsolete columns or rename columns. If you rename a Java field, Hibernate creates a new column and leaves the old one orphaned. For schema migrations on production, write explicit SQL migration scripts.

4. File Storage: Local Development vs Production

In application.yml, file.use-ftp: false by default for local development. Uploaded files (circulars, resumes) are saved locally into dr-project-main/uploads/ and served by FileServingController.java. In production on the Hostinger VPS, files can either be uploaded via FTP to Hostinger storage or written directly to /var/www/medexjob/uploads/, which Nginx serves directly for optimal performance.

8. Production Deployment Guide

Server Specs & Access

  • Hosting Provider: Hostinger VPS (Ubuntu Linux)
  • Domain: https://medexjob.com (Nginx reverse proxy with Let's Encrypt SSL)
  • Backend Service: Systemd unit medexjob-backend.service
  • Frontend Root: Static build deployed to /var/www/medexjob/

Deploying Backend Updates

# 1. Build production JAR locally
cd backend
mvn clean package -DskipTests

# 2. Copy the artifact to VPS
scp target/medexjob-backend-1.0.0.jar root@82.180.143.101:/opt/medexjob/backend/

# 3. On VPS, restart service and verify logs
sudo systemctl restart medexjob-backend
sudo systemctl status medexjob-backend
journalctl -u medexjob-backend -n 50 -f

Deploying Frontend Updates

# 1. Build production static bundle
cd frontend
npm run build

# 2. Copy dist directory contents to web root
scp -r dist/* root@82.180.143.101:/var/www/medexjob/

# 3. Ensure correct permissions on server
sudo chown -R www-data:www-data /var/www/medexjob
sudo chmod -R 755 /var/www/medexjob

9. Current Priorities & Handover Backlog

  1. Production Gemini API Key: Make sure the production systemd environment file has MEDEX_AI_API_KEY set so that circular extractions use Gemini 2.0 Flash in production.
  2. Razorpay Live Credentials: Payment gateway is currently configured with test API keys. Once business banking approval is completed, swap in production keys and verify the webhook handler at /api/payment/webhook.
  3. Candidate Job Alerts Engine: The database tables (JobAlert, NotificationPreferences) and notification services are built. A scheduled daily digest service can be wired up to email matching candidates when new circulars are published.
  4. Recruitment PDF Web Crawler (Roadmap): Currently admins upload circulars manually via the admin UI. An automated scraper targeting top medical institutes (AIIMS, PGIMER, JIPMER, state health portals) will automate the ingestion queue.
